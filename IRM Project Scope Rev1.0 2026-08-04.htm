การทำงานของระบบ

1.    Web App ที่ทำงานบน On-Premises เพื่อแสดงข้อมูล Delivery Date และ Quantity ของสินค้าที่เปิด PO ไปให้กับ Supplier แต่ละเจ้า และทำการ Update ใน Calendar และส่ง JSON ให้กับระบบ QMS ทุก Change ที่อยู่ในระยะเวลาการ Notify

2.    App จะมีหน้าหลักๆ ทั้งสิ้นดังนี้

-        System Setting ไว้สำหรับกำหนดค่าต่างๆของระบบโดย Admin เช่นตั้งค่า App Password สำหรับส่งเมล์, ตั้งเวลาส่งเมล์ไปหา Supplier, ระยะเวลาที่เก็บข้อมูลใน History, เวลาในการดึงข้อมูล Report 8 จาก SAP,

-        Authorize Matrix กำหนด User Group ว่าจะใช้งาน Menu อะไรได้บ้าง

-        User Management กำหนด User ที่จะเข้าใช้งาน

-        Supplier Master จะเป็นหน้าที่เก็บข้อมูลเพิ่มขึ้นเรื่อยๆจากข้อมูลที่ Query มาทุกวัน โดยจะมีข้อมูล Sup. Code, Sup. Name, Tel No. และ Email ซึ่งจะดึงมาจาก SAP

-        Calendar จะแสดงข้อมูลของ PO ที่จะส่งในวันนั้นๆ โดยถ้า Estimate จะแสดงสีส้ม, Confirmed จะแสดงสีเขียว เมื่อคลิ๊กก็จะแสดงรายละเอียดของสินค้าที่จะมาส่งในวันนั้นๆ ItemCode, Sup Name, Delivery Date, Quantity เป็นต้น

-        Item Master เก็บข้อมูลของ Item ใหม่ๆ เพื่อให้มีการใส่ค่า

1.    Lead Time ที่จะบอกว่า Item นี้ปกติจะมี Lead Time เท่าใด จะไม่มีการกำหนด Default

2.    Notify จะไว้ใส่ตัวเลขในการแจ้งเตือนล่วงหน้าโดย Default คือ 3 วัน

3.    ควรจะมีการแสดงอะไรบางอย่างว่า Item นี้เป็น New ยังไม่ได้ใส่ค่า Lead Time

-        Operation แสดงข้อมูลที่ดึงมาจาก Query Report 8 บน SAP มาแสดง ให้กับ User (PU Dept.) ทำการ ตรวจสอบและใส่ข้อมูลเพื่มเติม โดยข้อมูลที่เข้ามาในหน้านี้จะแสดงตามตัวอย่างด้านล่าง

-        ระบบจะ Query ข้อมูลบน SAP (อาจจะ Direct Query หรือจาก API) ทุกวันเวลา 04:00am (ปรับเปลี่ยนได้จากหน้า Setting) จากนั้นจะนำมาแสดงใหม่ให้ดูง่ายดาย โดยในแต่ละบรรทัดถ้า PO, Posting Date เดียวกัน แค่บรรทัดแรกบรรทัดเดียว

-        ใน 1 PO จะมีการสั่งสินค้าหลาย Item ได้ ในหน้า Operation เราจะจัดการทีละ Item โดย User จะกำหนดสองอย่างคือ

1. วันที่ส่งของ

2. จำนวนของที่จะส่งสำหรับ Item นั้นๆ

-        Item Code ที่แสดงในหน้า Operation นี้ ถ้ายังไม่มีในหน้า Master Item จะต้องทำการเพิ่มในหน้า Master Item ไว้ด้วย

-        ในแต่ละ Item จะมีการกด บวก โดย User เพื่อแตกวันที่ในการส่งและใส่จำนวนที่จะส่ง ของ Item นั้นๆ เพิ่มได้เองถือว่าเป็น Sub Item ที่แตกออกมาจาก Main Item เช่น Main Item ใส่ค่า Estimate Date และ จำนวนที่ส่ง และใน Sub Item ใส่ Estimate Date และ Quantity อีกค่าหนึ่ง ซึ่งสองอันจะไม่เกินจำนวนที่เปิดใน PO ตั้งแต่แรก

-        ในแต่ละวันที่ระบบไปดึงข้อมูลใหม่จาก SAP จะมาเช็คกับ Main Item เพราะข้อมูลจะถูก Update ที่จำนวน Quantity ที่มีการรับเข้ามาระหว่างวัน หรือการปรับเปลี่ยนตามข้อมูลของ Supplier

-        ถ้าแต่ละวันที่ระบบไปดึงข้อมูลใหม่จาก SAP และ Status ของ Item นั้นๆเป็น C คือมีการ Close แล้ว คือมีการรับของแล้ว ก็จะต้องทำการลบ Main Item นั้นๆออกไปจากหน้า Operation ย้ายไปยังหน้า History ซึ่งจะเก็บไว้ 7-15 วัน ตามหน้า System Setting ที่จะต้องให้ Admin เป็นการกำหนด Record History

-        ในหน้า Operation User จะใส่วันที่ที่คาดว่าของน่าจะมาส่ง และจำนวนสำหรับแต่ละ Item และอาจจะมีการกดบวกตามที่อธิบายในด้านบน ด้านล่างตัวหนังสือสีแดง คือวันที่มีการปรับวันที่คาดว่าของจะมาส่ง และวันที่จะNotify ล่วงหน้า ซึ่งวันที่ Estimate Arrival นี้อาจจะมาจาก User หรือ Supplier ซึ่งหาวิธีอย่างไรไม่ให้ Conflict กัน

3. Function ส่ง Mail ให้กับ Supplier

               - มีการกำหนดเวลาการส่งเมล์ในหน้า System Setting (เบื้องต้น 8:00am ของวันจันทร์ และพฤหัส) ให้ทำการส่งเมล์ไปหา Supplier ตาม Item ที่ได้เปิด PO ไปหา Supplier นั้นๆ โดยรวมเอาทุก PO ส่งไปพร้อมกัน

               - Supplier จะได้รับ URL แบบ Random เพื่อกดเข้าไปกรอกข้อมูลแต่ละ Item ของ PO โดย Supplier จะกรอกวันที่ประเมินว่าจะส่งของ และจำนวนสินค้าที่คาดว่าจะส่ง

               - Supplier ต้องสามารถกด บวก เพื่อแตกเป็น Sub Item ได้ด้วย กรณีที่ Supplier ต้องการจะแยกการส่ง Item ดังกล่าวเป็นการส่งแบบ Partial

- เมื่อกรอกข้อมูลเสร็จแล้วจะกด Submit โดยจะมีการ Submit ได้ครั้งเดียว URL ที่ส่งให้ Supplier นี้ก็จะ Expired ทันทีไม่สามารถเข้าใช้ได้อีก

               - ข้อมูลที่ Supplier ได้ทำการ Submit มาแล้ว จะมา Merge เข้ากับในหน้า Operation

               - ต้องมีการส่ง URL โดยอีเมล์ แบบ Manual โดย User ได้ หรือสามารถ Copy URL ส่งให้ทาง Line ได้ โดย User

 

สิ่งที่ยังไม่ชัดเจนและต้องให้ช่วยหา Solution ที่ชัดเจนและเป็นไปได้

1.    ปัญหาหน้า Operation
1.1 Item ที่มีการแก้ไข Estimate Date และ Quantity ในแต่ละ Item ไปแล้ว จะ Conflict กับที่ดึงมาใหม่จาก SAP หรือไม่

1.2          Item ที่มีการแก้ไข จะส่ง JSON หรือข้อมูลไปให้ระบบ QMS เมื่อใด ใช้ Trigger อะไร

1.3          Item ที่ Supplier มีการแก้ไขแล้ว จะเข้ามา Merge กับ Item ที่อยู่ในระบบได้อย่างไร จะต้องมีอะไรให้ยืนยัน จะรู้ได้อย่างไรว่า Merge แล้ว จะรู้ได้อย่างไรว่ามันมีการ Changed

2.    URL ที่ส่งให้ Supplier ทำอย่างไรให้มี Secure เนื่องจาก Supplier ไม่ได้มีการ Logon เข้ามา

3.    การเพิ่ม Sub Item ของ User จะทำงานอย่างไร และจะมีการ Conflict กับตอนที่ดึงข้อมูลมาใหม่หรือไม่

4.    เมื่อใดที่ควรจะส่ง JSON ไปแจ้ง QMS ต้องมี Trigger อย่างไร หรือต้องให้ User กด Accept ทีละ Item ซึ่งก็ไม่ค่อยสะดวก

5.    หน้า Calendar จะแสดงข้อมูลอย่างไรให้ดูง่าย และข้อมูลทุกจุดจะต้องอยู่ใน Format dd/mm/yyyy เท่านั้น

6.    การ Logon จะใช้การ Authen กับอะไรและบริหารจัดการตอน User ยังไม่ออก แต่จะยกเลิกการใช้งานอย่างไร

7.    ประเมินว่า IRM น่าจะใช้งาน On-Premises ซึ่งจะมี SAP B1 อยู่ที่ wa-dbs2.wa.net ไม่รู้ว่าการ Query ข้อมูลในหน้า Operation ที่แจ้งไปก่อนหน้า ควรจะใช้ Direct Query หรือ API หรือถ้าจะต้องสร้าง View เพื่อใช้งาน API ได้หรือเปล่า

8.    จะใช้ภาษาอะไรในการพัฒนา เนื่องจากตอนนี้มีแต่ Windows Server 2016 และไม่มี Docker ให้ใช้งาน หรือจะต้องติดตั้งที่ไหนอย่างไร

9.    คิดว่าอยากใช้ PostgreSQL เป็น DB จะติดตั้งที่ไหนอย่างไรเนื่องจากยังไม่มี Docker
